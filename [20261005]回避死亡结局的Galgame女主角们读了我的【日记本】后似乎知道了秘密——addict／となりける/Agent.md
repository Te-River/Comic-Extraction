## 增量更新方法
### 判小说新版
- 判新版的判据：**以下三者任一 > 34** 即判定有新话**（2026-10-05 实测三者均为 34）**
  1. `"__typename":"Episode"` 的**定义数**（实测 34）
  2. `"TableOfContentsChapter:"` 对象里 `episodeUnions` 数组的**长度**（实测 34）——源站该键名**带尾冒号、id 为空**，正则需按 `"TableOfContentsChapter:"\s*:\s*\{` 匹配
  3. `{"__ref":"Episode:(\d+)"}` 的**去重后**数量（实测 34）
- ⚠️ **不可用全页正则 `\{"__ref":"Episode:(\d+)"\}` 的原始命中数判新版**：该式实测得 **35**（去重后才是 34），因为首话 id `16818093090438857149` 会在 Work 对象的 `firstPublicEpisodeUnion` 字段里**额外再出现一次**。照原始命中数执行，下次增量首跑就会把「无新版」**误报成新话**
- 源站 Meta 块里的「全N話」字样可作旁证，但**以上述三项数值为准**
- ⚠️ **不要按 episodeId 大小判断新旧**：源站混用两段 id 空间（主线话 `1681809…`/`1681879…`，追加话出现过 `8221398…` 形式，数值上更小）。**以目录出现顺序为准**，新话接在 034 之后
- 新话名沿用源站标题，`035.<源站话名>.txt`；若新增的是番外性质内容且源站把它放在目录末尾，仍按顺序接号（保持全目录单一序列，与本次一致）

### 抓小说正文（已实测 4 次一致）
- **桌面 Chrome UA + `Accept-Language: ja`**，用 `Invoke-WebRequest` 或 Python `urllib` 即可拿到**含正文的 SSR HTML**
- ⚠️ **UA 只作建议、不作硬性前提**：曾观测到部分客户端取到 SPA 空壳（服务端 0 段落），但 2026-10-05 用 6 种 UA（Chrome 140 / iPhone Safari / Android / Googlebot / bingbot / IEMobile）复核**未能复现**——各 UA 段落数**一律 117**，字节数只有 51,735（桌面 + 爬虫）与 56,240（移动）两档。**该降级现象不可复现，不作因果断言**
- 判定「是否取到正文」以**段落数**为准（`js-episode-body` 内 `<p id="pN">` 计数），不要只看 HTTP 200 或字节数
- ⚠️ 当初误判「SPA 抓不到正文」的**真实成因**是下方「踩过的坑」第 4 条（PS 5.1 `Get-Content -Raw` 按 ANSI 解码日文乱码），**不是** UA
- 正文容器 `class="widget-episodeBody js-episode-body"`；右界取该容器内**首个 `</div>`**（避开尾部导航）
- 段落 `<p id="pN">`；空行段 `<p id="pN" class="blank">`
- 剥标签必须用**引号感知**正则：`<[a-zA-Z][^>"']*(?:"[^"]*"|'[^']*'|[^>"'])*>`。朴素的 `<[^>]+>` 会在带引号属性的地方截断
- 顺序：先删 `<rt>…</rt>` → 再剥标签 → `<br><br>`→空行、`<br>`→换行 → HTML 实体反转义（`&amp;`→`&`）
- 落盘 UTF-8 无 BOM / LF

### 踩过的坑（逐条实测，勿重复踩）
1. **PowerShell 5.1 的 `.ps1` 里不要放日文等非 ASCII 字面量** —— 按 ANSI 解码导致语法报错。改用 UTF-8 外部数据文件 + `[IO.File]::ReadAllText(…, UTF8)` 读取
2. **本目录名含 `[` `]`，PowerShell 必须用 `-LiteralPath`**，否则通配符解析失败（`Get-ChildItem` / `Test-Path` / `Join-Path` 都会踩）
3. **临时文件清理绝不能用 `*.txt` 通配删除** —— 本轮有一次 implementer 因此把自建的 `_check.txt` 误拷进 `txt\`，也差点误删归档文件。只按写下的完整文件名逐个删
4. **校验用文字匹配时要显式指定 UTF-8**。`Get-Content -Raw` 在 PS 5.1 默认按 ANSI 解码，会把日文变成乱码，导致「正文不存在」的**假阴性**——本次排查「正文是否 SSR」时被这个坑误导过一轮
5. 抓取脚本只放 OS temp 目录（`C:\Users\34296\AppData\Local\Temp\opencode`），**不进项目目录**
6. 串行抓取、留延时，不并发压测
