# Comic-Extraction · 漫画归档

引导 Agent 依据你提供的线索，定位并抓取**国内可直接访问**的漫画汉化版本——页面图、正文文本，以及存在时的原作小说——按统一规范归档到本地，供留存、追更与阅读器使用。

> 本仓库是**规范与档案仓库**，不是素材仓库。
> 抓取下来的图片与正文体积大、且属第三方作品，一律只存本地、不入库（见下方「为什么仓库里没有漫画」）。

## 📖 看不懂？去看示例

`示例/` 里不是空壳占位，而是一份能直接照着做的范例：

- **完整 `Agent.md`**——模板逐栏填好，含运行状态、检查点写法、增量更新方法，以及**原作小说「已归档」与「未获取」两种写法的对照**
- **4 份真实文本**——`txt/ja/` 原文与 `txt/zh-CN/` 机翻逐条对应，看得出语种分层，以及机翻为什么要带 `.机翻` 后缀
- **完整的「自译与术语」区**——示范机翻标记、术语表写法，以及一个把机翻说成汉化的反面示例
- **10 张真实 JPEG**——按页存储，5 页/章，可正常解码、尺寸统一（850×1200），图上标了语种、章号与页号
- **完整目录树**——`jpg/<语种>/<章节>/<页号>.jpg` 三层，外加 `txt/<语种>/`，以及隐藏的 `.tmp/`

示例内作品名、作者、URL 全是**虚构占位符**（URL 一律 `example.com`），不可当作真实来源。示例目录名刻意保留 `[xxxxxxxx]`；真实归档跑完后会显示 8 位日期。真实任务目录一律放在**项目根目录**，不进 `示例/`。

## 为什么仓库里没有漫画

`.gitignore` 排除了全部归档素材（`jpg` / `png` / `webp` / `txt` / `epub` / `cbz` 等），只保留规范文档与演示结构。两个原因：

1. **素材是第三方作品**，公开仓库不适合承载。
2. **git 历史无法真正删除已推送的大文件**。单张漫画页可达十几 MB，一次归档就是几百 MB；一旦入库，体积会随每次追更永久累积，且无法干净清除。

素材就放在你本地的这个目录里，不进版本库。`示例/` 是例外：里面的图片与文本都是**为演示而生成的虚构内容**（图片是可解码的占位页，文本是自撰的示例段落），不含任何真实作品素材，因此可以入库充当命名约定的活文档。

## 目录与命名规范（简版）

一部漫画 = 一个文件夹：

```
[xxxxxxxx]漫画名称——作者
```

| 组成 | 规则 |
|---|---|
| `xxxxxxxx` | 该漫画**最近一次成功运行的结束日期**，8 位无分隔符。2026-06-11 → `20260611` |
| `漫画名称` | 通行中文名 |
| `——` | 两个 `U+2014 EM DASH`（不是 `U+2015`，不是 `--`） |
| `作者` | 查不到就写 `未知作者`，不编造 |

目录内部：

```
[20260611]漫画名称——作者\
├─ Agent.md          该漫画的独立档案：运行状态、来源、版本、已归档范围、追更方法
├─ .tmp\             隐藏目录，临时文件与脚本；任务结束后整个删除
├─ jpg\              图片目录，名字 = 实际扩展名，全小写
│  ├─ ja\           日文原图
│  │  ├─ 001.第一章\   章节目录
│  │  │  ├─ 001.jpg    页文件，章内连续编号
│  │  │  └─ 002.jpg
│  │  └─ 002.第二章\
│  │     └─ 001.jpg
│  └─ zh-CN\        汉化图，章号页号与 ja/ 一一对应
│     ├─ 001.第一章\
│     │  ├─ 001.jpg
│     │  └─ 002.jpg
│     └─ 番外\      非正篇，其下仍是章节目录
│        └─ 001.特典\
│           └─ 001.jpg
└─ txt\              文本目录，名字 = 实际扩展名，全小写
   ├─ ja\           日文原作
   │  └─ 001.第一章.txt
   └─ zh-CN\        中译
      └─ 001.第一章.txt
```

> 上图对应「原作文语为日语」的情形。若**原作就是中文**，则不套语种目录，文件直接放在 `jpg/`、`txt/` 下。
>
> **图片按页存，文本不分页**：图片一章一个目录、目录内一页一个文件；台词与小说正文一话一个 `.txt`。

要点：

- 素材目录名**跟着实际抓到的格式走**。抓到 `.png` 就叫 `png/`，不存在「先建 jpg 再把 png 塞进去」。
- 章节目录名 `3位补零序号.章节名`，页文件名 `3位补零页号.扩展名`：`001.第一章/001.jpg`。
- **不把整章拼成一张长图。** 实测一章 31 页拼成 1200×51151 约 19.7 MB；按页存后阅读器可懒加载、坏页能单独重抓。
- **补零是硬性要求**：不补零的话字符串排序得到 `1. → 10. → 2.`，序号照样乱。补零后**按文件名直接排序就是正确顺序**，阅读器无需任何额外逻辑。
- **图片和文本都要分语种**：原作非中文就建 `ja/`（原文）与 `zh-CN/`（汉化），两边序号一一对应；原作是中文就不套语种目录。
- 判断「原作是什么语言」依据**实际内容**，不依据中文译名——中文译名会掩盖日文原作。
- `.tmp/` 只在**任务未完成**时存在，用来存放分页缓存、待拼接页图和辅助脚本，以便中断后立即恢复。一旦确认完成就整目录删除，防止目录滚雪球。
- 日期前缀只在**本次运行确实产出并通过校验**时刷新；失败则保持原值不动。

## 归档与小说的优先级

**原作小说与漫画同等重要**，是并列的必做交付物，不是可选项。Agent 会同时推进**图源、文本源、原作小说源**三条线。找不到原作小说允许，但必须在档案里写明检索过哪些渠道、为什么拿不到——不接受静默跳过。

## 找不到汉化时自行翻译

纯文本内容（小说正文、台词）确认没有可访问的汉化源时，**由 Agent 自行翻译**，产出中文文本放进 `zh-CN/`。规则见 `Agent.md` §2.7。

| 对象 | 能否自译 |
|---|---|
| 原作小说正文、漫画台词 | **可以**，逐话译成 `.txt` |
| 漫画页面图 | **不可以**——汉化图要在原图上覆盖译文，必然损伤画面。找不到汉化图时交付「原图 + 中文文本」 |

三条硬规矩：

1. **机翻必须标记**：文件名加 `.机翻` 后缀（`001.第一章.机翻.txt`），档案逐条列出。绝不写成「汉化」「官方译本」——机翻被误认成官方汉化，整份档案的可信度就没了。
2. **维护术语表**：人名、专名、称谓固定下来放档案里。**多义词按语境分行**——「先生」在教师场景是「老师」、在诊所是「医生」、泛指成年男性时是「先生」，不能一词一译到底。长篇会被拆到多次运行逐章翻译，没有术语表会读起来像好几个人各翻各的。
3. **按语境定译，必要时查资料**：译意不译词，含义由场景决定。拿不准的词、专名、典故就去查（走浏览器通道），查到什么、依据是什么记进术语表。
4. **可续比快重要**：逐话写入并回写检查点，中断后从断点继续。

日后若出现官方汉化，机翻**不静默删除**，在档案标注后由用户决定去留。

## 中断可恢复

目录骨架在任何联网动作**之前**就建好，之后每完成一大步就回写该漫画的 `Agent.md`（记录当前步骤、已完成章节区间、失败章节、中断位置、**下一步动作**）。因此额度耗尽或意外中断后，下一个 Agent 读档案即可从断点继续，不必重新翻来源。

完整规则见 [`Agent.md`](Agent.md)。

## 怎么用

1. 把漫画名、作者、已知链接等线索告诉 Agent
2. Agent 依 `Agent.md` 定位可直连的来源，抓取并按规范落盘
3. 每部漫画在自己的 `Agent.md` 里记下来源与追更方式
4. 之后追更只需说「更新 X」，Agent 读该漫画的档案即可只抓新增章节

Agent 只处理**公开可访问**的来源。遇到登录墙、付费墙会停下并告知，不绕过。
